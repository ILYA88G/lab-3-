# Book Catalog — каталог библиотечных книг

Лабораторная работа №3 по дисциплине «Программирование на языке Python».

Программа реализует каталог библиотечных книг: добавление, получение, удаление и поиск объектов, а также сохранение и загрузку JSON. Книги хранятся в словаре по уникальному идентификатору. Для поиска по категориям поддерживается дополнительный неуникальный индекс.

Реализованы валидация данных, собственные исключения, отмена операций, представление только для чтения, миграция JSON и транзакции с автоматическим откатом при ошибке.

├── demo.py              # демонстрация возможностей проекта

Путь данных: создание `Book` → проверка полей → добавление в `Catalog` → операции с каталогом → сохранение в JSON.

При загрузке: JSON → проверка структуры и версии → миграция при необходимости → создание `Book` → заполнение нового `Catalog`.

## Модель данных

Сущность `Book` реализована через `@dataclass(frozen=True)`.

| Поле | Тип | Описание |
|---|---|---|
| `item_id` | `str` | Уникальный идентификатор книги |
| `name` | `str` | Название |
| `category` | `str` | Категория или жанр |
| `year` | `int` | Год публикации |
| `author` | `str` | Автор |
| `pages` | `int` | Количество страниц |

В `__post_init__()` проверяются инварианты:

- Строковые поля должны быть непустыми строками, не состоящими только из пробелов.
- Год должен иметь тип `int` и находиться между 1 и текущим годом включительно.
- Число страниц должно иметь тип `int` и быть положительным.
- При нарушении инвариантов возникает `InvalidItemError`.
- Уникальность `item_id` контролируется каталогом при добавлении книги.

`frozen=True` предотвращает обычное присваивание новых значений полям после создания объекта.

## Операции каталога

| Метод | Назначение |
|---|---|
| `add(item)` | Добавить книгу; отклонить повторяющийся ID |
| `get(item_id)` | Получить книгу по ID |
| `remove(item_id)` | Удалить книгу по ID |
| `find_by_category(category)` | Найти книги по категории |
| `find_by_name(query)` | Найти книги по подстроке названия |
| `__len__()` | Получить количество книг |
| `__iter__()` | Перебрать книги в порядке добавления |
| `__contains__(item_id)` | Проверить наличие ID |

Основное хранилище `_items` — словарь `dict[str, Book]`. Поиск по ID выполняется в среднем за O(1).

Категории нормализуются с помощью `strip().casefold()`. Названия сравниваются через `casefold()`, поиск выполняется по подстроке без учёта регистра. Методы поиска возвращают новые списки; при отсутствии совпадений возвращается `[]`.

Порядок итерации определяется порядком добавления. После удаления и повторного добавления книга оказывается в конце каталога.

## Хранение JSON

Функция `save_catalog()` записывает каталог в UTF-8 с отступами и `ensure_ascii=False`. Функция `load_catalog()` загружает и проверяет документ.

Текущая версия формата — **2**:

```json
{
  "format_version": 2,
  "catalog": {
    "books": [
      {
        "item_id": "item-7319",
        "name": "Война и мир",
        "category": "Роман",
        "year": 1869,
        "author": "Лев Толстой",
        "pages": 1225
      }
    ]
  }
}
```

Поле `format_version` обозначает версию структуры файла, а не версию содержимого каталога. Операции добавления и удаления книг его не изменяют.

### Миграция формата

Поддерживаются две структуры:

- **Версия 1:** `{"format_version": 1, "books": [...]}`.
- **Версия 2:** `{"format_version": 2, "catalog": {"books": [...]}}`.

При загрузке версии 1 функция `migrate_v1_to_v2()` преобразует структуру в памяти. Исходный JSON-файл не перезаписывается. Новые файлы сохраняются в версии 2. Неподдерживаемая целочисленная версия вызывает `UnsupportedFormatVersionError`.

### Обработка повреждённых файлов

Загрузчик проверяет корневую структуру документа, тип версии, список книг, поля объектов и отсутствие дубликатов ID. Некорректное содержимое вызывает `CorruptedFileError`.

`load_catalog()` создаёт отдельный каталог и возвращает его только после полной успешной проверки. Если загрузка прерывается на ошибке, частично заполненный каталог не возвращается, а существующие каталоги не изменяются.

## Ошибки и исключения

Все предметные исключения наследуются от `CatalogError`.

| Исключение | Назначение |
|---|---|
| `CatalogError` | Базовое исключение каталога |
| `InvalidItemError` | Некорректный объект или его данные |
| `DuplicateIDError` | Повторяющийся ID |
| `ItemNotFoundError` | Книга по ID не найдена |
| `UnsupportedFormatVersionError` | Неподдерживаемая версия JSON |
| `CorruptedFileError` | Некорректный JSON или данные каталога |

Исключения генерируются в соответствующих методах; ожидаемые ошибки в `demo.py` обрабатываются вызывающим кодом через `try/except`. Ошибки файловой системы, например `FileNotFoundError`, могут передаваться вызывающему коду без преобразования.

## Реализованные дополнительные задания

### 1. Неуникальный индекс по категориям (+3)

Словарь `_category_index` сопоставляет нормализованную категорию со списком ID книг. Индекс обновляется при добавлении, удалении и отмене операций. Поиск по категории не требует полного перебора каталога.

### 2. Отмена последней операции — `undo()` (+3)

История `_undo_stack` хранит обратимые операции добавления и удаления. `undo()` отменяет последнюю успешную операцию, восстанавливая порядок книг и индекс категорий. Неудачные операции в историю не попадают.

### 3. Представление только для чтения (+2)

`CatalogReadOnlyView` предоставляет операции чтения, поиска и итерации, но не содержит публичных методов `add()`, `remove()` и `undo()`. Представление связано с исходным каталогом и отражает его изменения без копирования всех книг.

### 4. Миграция JSON v1 → v2 (+2)

Загрузчик поддерживает старую структуру и преобразует её к текущей версии перед созданием объектов. После миграции данные проверяются обычным механизмом загрузки.

### 5. Транзакционный контекстный менеджер с rollback (+5)

`transaction()` реализован с помощью `@contextmanager`:

```python
with catalog.transaction():
    catalog.add(book1)
    catalog.add(book2)
```

При нормальном завершении блока изменения сохраняются. Если исключение выходит из блока `with`, операции текущей транзакции отменяются в обратном порядке. Восстанавливаются состав каталога, порядок итерации и индекс категорий; исключение передаётся вызывающему коду.

Вложенные транзакции запрещены, как и ручной `undo()` внутри транзакции. После успешной транзакции её операции можно отменять по одной с помощью `undo()`.

**Итого реализовано 15 дополнительных баллов из 20 возможных.** Задание по истории версий без полного копирования каталога (+5) не реализовано.

## Принятые решения

- Для эффективного поиска по ID используется словарь; для поиска по категории — вспомогательный индекс.
- Порядок обхода каталога детерминирован и совпадает с порядком добавления.
- Результаты поиска возвращаются отдельными списками, а `Book` защищён от обычного изменения полей.
- Отмена операций и откат транзакций основаны на истории изменений, без создания полной копии каталога при входе в транзакцию.
- Транзакция откатывается при исключении, вышедшем за границы блока `with`; перехваченное внутри блока исключение само по себе не вызывает откат.
- Версия формата JSON не зависит от числа изменений в каталоге.
- CLI не требуется: работа программы показана в `demo.py`.
